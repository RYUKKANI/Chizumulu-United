# Chizumulu United Club Manager

사이트: https://ryukkani.github.io/Chizumulu-United/

회원가입 → 관리자 승인 → 로그인 후 구단 기록 공동 관리 방식입니다. 사용자는 GitHub 토큰을 발급하지 않습니다. 화면은 GitHub Pages, 회원 인증과 구단 기록은 Supabase에서 제공합니다.

## 회원과 권한

- 신규 가입자는 항상 **일반 회원 / 승인 대기** 상태입니다. 가입 요청에 관리자 권한을 넣어도 적용되지 않습니다.
- **일반 회원:** 승인 후 선수·사진·경기·구단 기록을 조회하고 수정하고 JSON 백업을 내려받습니다.
- **관리자:** 일반 회원 기능과 함께 회원 검색, 가입 승인, 관리자 권한 부여·회수, 비활성화·이용 재개를 합니다.
- 비활성 회원과 승인 대기 회원은 자기 가입 상태만 확인할 수 있습니다. 다른 회원 목록과 구단 기록에는 접근할 수 없습니다.
- 마지막 사용 중인 관리자는 비활성화하거나 강등할 수 없습니다. 동시에 두 관리자가 서로를 강등해도 서버에서 검사합니다.
- 회원 변경은 감사 기록에 남습니다. 비활성화는 계정이나 구단 기록을 삭제하지 않습니다.

## 처음 연결하기

`config.js`는 이 사이트의 Supabase 프로젝트에 연결되어 있습니다. 새 프로젝트로 이전할 때는 아래 설정을 진행하고, 첫 관리자와 기존 기록 이전을 완료한 뒤 배포하세요.

1. Supabase 프로젝트를 만듭니다. 공개 사이트 코드를 위한 프로젝트이므로 선수 정보나 사진을 공개 저장소에 넣지 않습니다.
2. SQL Editor에서 `supabase/migrations/202610010001_members_and_club.sql`을 실행합니다. 새 프로젝트용 최초 마이그레이션이며, 재실행하거나 기존 데이터를 초기화하는 용도로 사용하지 않습니다.
3. Authentication에서 이메일·비밀번호 가입과 신규 가입을 허용합니다. 비밀번호 최소 길이를 **10자**로 설정합니다.
4. Authentication의 Site URL과 허용 Redirect URL에 `https://ryukkani.github.io/Chizumulu-United/`를 등록합니다.
5. 소규모 관리자 승인 방식에서는 **Confirm email을 끄고** 시작할 수 있습니다. 이 경우 이메일 소유 확인은 하지 않으며, 관리자가 실제 사용자를 확인한 뒤 승인해야 합니다. 이메일 확인·비밀번호 찾기를 사용하려면 먼저 Custom SMTP를 연결하고 이메일 발송을 검증하세요. 기본 이메일 발송 서비스는 일반 운영용으로 가정하지 않습니다.
6. `config.js`에 프로젝트 URL과 **publishable key**를 입력합니다. 기존 anon key도 지원합니다. **secret key 또는 service_role key는 절대 넣지 않습니다.** 이메일 재설정 기능은 SMTP 검증 후 `emailRecoveryEnabled: true`로 켭니다.
7. 새 화면을 별도 미리보기에서 열어 첫 관리자 이메일로 가입합니다. SQL Editor에서 `supabase/bootstrap-admin.sql`의 이메일을 바꾼 뒤 실행합니다. 이 작업은 최초 관리자 한 명만 설정합니다. 누구나 첫 가입만으로 관리자가 되는 기능은 없습니다.
8. 기존 구단 기록을 첫 관리자의 **데이터 백업 → 백업 불러오기**로 가져옵니다. 기존 사이트의 JSON 백업과 GitHub `club-state.json` 파일을 모두 그대로 지원합니다. 기존 비공개 저장소는 이 작업으로 삭제하거나 변경하지 않습니다.
9. 두 계정으로 가입 승인, 권한 변경, 비활성화와 저장 동작을 확인한 뒤 `main`에 반영합니다. GitHub Pages는 `main` 루트에서 배포합니다.

## 저장과 충돌 처리

- 구단 기록과 사진은 승인된 회원만 읽을 수 있는 `club_state`에 저장합니다. 기존 데이터 형식을 유지하며 현재 크기 상한은 8 MiB입니다.
- 읽기에는 RLS를 적용하고 직접 쓰기 권한은 주지 않습니다. 저장과 회원 변경은 서버 함수에서 인증·권한을 검사합니다. 화면 버튼만 숨기는 방식이 아닙니다.
- 저장은 버전 확인과 잠금으로 처리합니다. 다른 회원이 먼저 저장하면 내 변경 내용을 보존하고 충돌을 알립니다. 응답이 끊긴 저장 요청은 변경 ID로 중복 적용을 막습니다.
- 실패한 변경 내용은 현재 기기의 IndexedDB에 **프로젝트와 회원별로 구분**하여 보관합니다. 같은 계정으로 다시 로그인하면 복구합니다. 공유 기기 사용 후에는 로그아웃하고 필요하면 브라우저의 사이트 데이터를 지우세요.
- 다른 회원의 변경과 회원 상태는 화면을 다시 열거나 20초마다 확인합니다. 비활성 계정의 서버 접근은 다음 요청부터 차단됩니다.
- 로그인은 유지되며 세션 갱신은 Supabase SDK가 처리합니다. 비밀번호는 앱의 저장 공간·백업·구단 데이터에 보관하지 않습니다.
- 전체 JSON 백업 다운로드와 복원은 유지합니다. 회원 서비스가 여러 파일로 구성되므로 기존의 단일 HTML 다운로드는 제공하지 않습니다.

## 구단 운영 기능

- **대시보드:** 잔액·미지급 수당, 구매할 물품, 다음 경기 징계와 훈련 공지를 모아 봅니다. 승인된 모든 회원이 운영 기록을 입력·수정합니다.
- **수입·지출:** MWK 장부, 기초 잔액, 선수별 수당 발생과 부분 지급을 기록합니다. 수당 지급은 지출 한 건에 연결되므로 이중 합산되지 않습니다. 잘못 입력한 지급을 취소하면 장부와 미지급금이 함께 복원되고 취소 이력은 남습니다.
- **장비·의무 물자:** 재고·구매와 지급·반납을 한 메뉴의 탭으로 관리합니다. 기존 장비·지급·반납 기록을 사용합니다. 가용 재고는 총수량에서 파손·분실, 지급중 수량과 사용·소모분을 뺍니다. 최소 기준 이하 품목은 빨간 배지와 Nkhata Bay 쇼핑 리스트에 표시됩니다. 목표 수량을 등록하면 필요한 구매량을 계산합니다.
- **훈련·출석:** 주간 출석·본업과 상세 훈련 기록을 한 메뉴의 탭으로 관리합니다. 선수 프로필의 본업과 반복 요일을 입력합니다. 주간 표의 회색 본업 일정은 예정 불참이며 실제 결석 기록을 만들지 않습니다. 특정 날짜만 예정 일정을 바꿀 수 있고 실제 출석·지각·결석은 기존 훈련 기록에 연결됩니다. 미래 날짜의 실제 출석은 입력하지 않습니다. 한 날짜에 훈련이 여러 번 있으면 훈련 기록 탭에서 수정합니다.
- **카드·출전 정지:** 경기 기록의 경고·퇴장을 대회별로 계산합니다. 실제 규정 출처·계산 시작일·경고 기준·정지 경기 수를 입력하고 적용 체크를 켜야 합니다. 3장·1경기는 예시값입니다. 과거 시즌 합계는 경기 시점을 알 수 없어 자동 반영하지 않으며 선수별 기초 누적에 직접 입력합니다. 날짜 없는 경기는 계산에서 제외하고 표시합니다. 완료된 같은 대회 경기에서 미출전이면 정지를 1경기 소화하고, 연기된 경기나 다른 대회는 소화에 포함하지 않습니다. 정지 중 출전 기록은 확인 경고를 띄웁니다. 정지 선수의 선택을 제한하고 기존 명단에 남아 있어도 저장을 막습니다.
- **호수 기상:** 대시보드에서만 기상과 훈련 공지를 확인·수정합니다. 치주물루의 Open-Meteo 예보에서 풍속·풍향·돌풍과 당일 최대 강수 확률을 받아 30분마다 갱신합니다. 말라위 시간(CAT)을 사용합니다. 최근 받은 예보는 기기에 보관하고 한 시간 이상 지난 자료나 연결 실패를 표시합니다. 호수 파도 높이는 제공 자료가 없어 **미제공**으로 표시합니다. 현지 배편·훈련 변경 공지는 회원이 직접 입력하고 토글합니다.

**구단 지원**에는 코치진·원정·후원·연락처를 모으고 장비 항목은 장비·의무 물자 메뉴로 통합했습니다. 선수 이름은 목록·출석·징계·명단·선택 항목에서 등록된 영어 이름과 한글 이름을 함께 표시합니다. 이름 원본과 기존 기록은 유지합니다.

운영 정보는 기존 `club_state`의 `operations`에 저장되며 같은 버전 확인·권한 검사·충돌 복구를 사용합니다. 전체 JSON 백업에도 포함됩니다. 기존 백업에는 새 항목이 없어도 불러올 수 있습니다. 신규 재정·장비 기록은 예시 데이터 없이 시작합니다.

## 검증

Node.js 설치 후 `npm install`을 실행합니다.

```sh
npm run test:db
npm run test:operations
npx playwright install chromium
npm run test:browser
```

데이터베이스 테스트는 PGlite의 실제 PostgreSQL 엔진에서 권한·승인·강등·비활성화·중복 저장·버전 충돌을 검증합니다. 브라우저 테스트는 실제 화면과 Supabase SDK를 사용하며 테스트 인증 응답을 PostgreSQL과 연결합니다. 실제 Supabase 프로젝트와 이메일 발송 검증은 운영 연결 후 별도로 확인해야 합니다.

공식 문서: [회원 인증](https://supabase.com/docs/guides/auth/passwords), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [서버 함수](https://supabase.com/docs/guides/database/functions).

## 통합 업무 화면

대시보드, 선수단, 경기 관리, 훈련 관리, 구단 운영의 다섯 메뉴를 사용합니다. 관리·설정에서 회원 승인, 구단 설정과 백업을 관리합니다.

선수 명단은 한글·영어 이름, 참가 상태, 최근 경기와 훈련 기록을 표시합니다. 선수 상세는 요약, 경기 기록, 훈련 기록, 상태·징계, 감독 메모, 계약·서류 탭으로 나뉩니다. 최근 기록이 없으면 미입력으로 표시합니다.

훈련 계획은 `trainingPlans` 배열로 기존 공용 구단 상태와 함께 저장·백업됩니다. 기존 백업에 이 항목이 없어도 불러올 수 있습니다. 출석·본업은 기존 훈련 기록을 함께 사용하며, 본업이 미설정인 선수는 참가 예정으로 가정하지 않습니다. 장비 재고·구매와 지급·반납은 구단 운영 안에서 관리합니다.

경기 명단 배치는 포메이션과 선수의 주포지션을 기준으로 자동 표시합니다. 드래그 전술 편집은 지원하지 않습니다. 임시 미리보기의 선수 백업·사진과 시험 기록은 공개 파일에 포함하지 않습니다. 기존 인증, 승인, 저장 충돌 처리와 서버 권한 검사를 유지합니다.
